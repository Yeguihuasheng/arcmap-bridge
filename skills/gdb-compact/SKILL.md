# 批量压缩地理数据库

## 功能
扫描指定目录下的全部文件地理数据库（*.gdb），逐个执行 Compact 压缩，回收因频繁增删要素而膨胀的存储空间、降低体积。适用于项目收尾归档前的 GDB 批量瘦身。

## 输出
- 逐个打印每个 GDB 的压缩结果（成功/非 GDB 跳过/失败原因）。
- 压缩是原地操作，不产生新文件；体积缩减量取决于历史碎片程度。

## 使用前提
- 目标 GDB 不能被 ArcMap / ArcCatalog 等独占打开，否则报错。
- 只处理 `.gdb` 结尾的文件地理数据库；个人地理数据库（.mdb）请用 `gdb-to-mdb` 的同类逻辑自行处理。



## 使用前必须先问询（缺一不可）
用 AskUserQuestion 逐项确认下列参数，全部明确后才执行；不确定的给候选值让用户选：

- 扫描哪个目录？该目录下所有 .gdb 都会被压缩，是否确认范围？
- 压缩前是否已关闭所有占用这些 GDB 的程序（ArcMap/ArcCatalog）？（有进程占用时 Compact 会失败）

## 执行路径
直接执行本技能的 `scripts/run.py`（参数按上表顺序传入）。运行环境：ArcMap

## 执行后复核
- 读回输出的行数/字段值或打开结果文件抽查 3 项；
- 报错时看 traceback 定位到具体参数。

## 参数与调用
```bat
python scripts\run.py <要扫描的目录（其下的 *.gdb 全部压缩）>
```
参数说明：

1. 要扫描的目录（其下的 *.gdb 全部压缩）
