# 按字段对照表合并异构要素类

## 功能
读一张字段对照表 CSV（每行：源要素类路径、原字段名、目标字段名），先逐个把源数据投影到统一坐标系，再把每个字段按对照关系搬到目标字段名下，最后合并成一个要素类并保留 `MERGED_SRC` 记录来源路径。用于把多年/多批次/多县市字段命名不一致的成果拼成一张总表。

## 使用前提
- 对照表 CSV 需要三列：`feature_path`、`from_field_name`、`to_field_name`，首行可以是中文表头（会自动跳过）。
- 源数据坐标系不一致时会自动 `Project`；**跨带/跨基准请用 `tool-coordsys-batch` 先确认变换参数**，本脚本按 ArcGIS 默认地理变换处理。
- shapefile 字段名上限 10 字符，`to_field_name` 超长会被截断，建议输出到文件地理数据库。
- 字段搬运用的是「新建目标字段 + 计算赋值」，源字段本身不改；目标字段类型按源字段类型推断，多个源类型冲突时以第一个为准。
- 输出会多一个 `MERGED_SRC` 文本字段（255），值是该条记录来自哪个要素类。
- 与 `tool-batch-merge` 的分工：后者要求各图层字段本来就是一致的；本技能专门处理**字段命名不一致**的情况。



## 使用前必须先问询（缺一不可）
用 AskUserQuestion 逐项确认下列参数，全部明确后才执行；不确定的给候选值让用户选：

- 字段对照表 CSV 在哪？（data-field-cross-ref 生成的那种）
- 合并结果输出到哪里（要素类全路径）？
- 统一到哪个坐标系？（给 .prj 路径或工厂代码，如 CGCS2000 填 4490）
- 最终只保留哪些目标字段？（全保留就填 #）

## 执行路径
直接执行本技能的 `scripts/run.py`（参数按上表顺序传入）。运行环境：ArcMap

## 执行后复核
- 读回输出的行数/字段值或打开结果文件抽查 3 项；
- 报错时看 traceback 定位到具体参数。

## 参数与调用
```bat
python scripts\run.py <字段对照表 CSV（feature_path,from_field_name,to_field_name）> <输出合并后的要素类> <目标坐标系（.prj 文件路径 / 坐标系名 / 工厂代码，如 4490）> <要保留的目标字段，分号分隔（填 # 表示保留全部）>
```
参数说明：

1. 字段对照表 CSV（feature_path,from_field_name,to_field_name）
2. 输出合并后的要素类
3. 目标坐标系（.prj 文件路径 / 坐标系名 / 工厂代码，如 4490）
4. 要保留的目标字段，分号分隔（填 # 表示保留全部）
